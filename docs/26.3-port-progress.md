# Fabric 26.3 Port Progress

Last updated: 2026-10-19

## Latest CI evidence

Workflow run `39293135480` on branch `fabric-26.3-port/access-widener-and-bone-injection`, commit `e3687417`.

- Kotlin compiler diagnostics: 4,913 lines beginning with a source-file diagnostic (down from 6,001 in the first supplied log).
- Affected source files: 598 (down from 932).
- The build now reaches `:compileKotlin`; the access widener and interface injection are applied successfully.
- Minecraft 26.3 has no intermediary mapping layer in this build, so the project access widener must declare the `official` namespace. A `named` widener fails during Loom's jar processing.

The remaining diagnostics are clustered around the 26.3 GUI extraction and rendering rewrite plus registry/item API changes:

- GUI drawing helpers still declare `PoseStack` while `GuiGraphicsExtractor.pose()` returns `Matrix3x2fStack` (the largest single group).
- Immediate-mode rendering types (`MultiBufferSource`, `RenderStateShard`, the old `RenderType` package and its composite state builders) no longer exist; they need the new render-type/`SubmitNodeCollector` pipeline.
- Registry and item APIs changed: `SignItem`, `MenuType.register`, `RecipeBookCategories`, `VillagerTrades.ItemsForEmeralds`, `ItemColor`/`BlockColor`, and `Item.Properties` helpers.
- Entity/vehicle and criterion registration types changed (`Boat`, `CriterionTrigger`, registry generics).
- Scroll and widget event APIs use the new `MouseButtonEvent`/`KeyEvent` objects and private scroll fields need accessors.

## Implemented so far

- Separate `fabric-26.3` Gradle target and CI workflow.
- 26.3 access widener (`fabric-26.3/src/main/resources/cobblemon-26.3.accesswidener`) with only entries that resolve against the 26.3 jar, declared in the `official` namespace.
- `ModelPart` interface injection via `loom:injected_interfaces` in the target `fabric.mod.json`.
- Posable model skeleton APIs now use `ModelPart` directly instead of relying on the injected `Bone` interface; this removed the large `rootPart`/`head` subtype clusters.
- GUI callbacks renamed to `extractRenderState`/`extractWidgetRenderState`, and `GuiGraphicsExtractor.drawString` calls moved to `text`.

## Current blocker and next focus

Compilation is still blocked. The next coherent batch should convert the shared GUI drawing helpers (`blitk`, `drawRectangle`, tooltips) from `PoseStack`/`Tesselator` to `GuiGraphicsExtractor` and `Matrix3x2fStack`. After that, migrate render types and the buffer/provider pipeline, then registries/items, entities, and data/recipes. Re-run CI after each batch and base the next edits on the new `diagnostics.txt` and `build.log`.

The workflow also publishes the first compiler errors and diagnostic totals as check annotations, because downloading logs and artifacts requires repository write access.
